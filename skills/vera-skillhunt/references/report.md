# 选用报告规范

面向希望选用 Skill 的用户，解释决策与使用方法。遵从用户给出的语言和视觉参照；未指定时使用清晰的中文页面，不把某次案例的配色固定成所有报告的风格。

## 内容结构

1. **任务与建议**：目标、关键条件、推荐及理由；结论放在前面。
2. **候选对比**：按实际需求比较用途、输入、输出、运行条件、上手成本和已知限制；给出适合与不适合的情况。
3. **逐项上手**：展示名、准确调用名、原始来源、准备材料、简短使用步骤、可复制的任务提示词。
4. **证据与状态**：文档介绍、作者示例和本次实测分别标记；安装状态单列。没有实测时说明尚未验证效果，不生成虚构的效果图或评分。
5. **结果与下一步**：已有产物可点击查看；缺少什么、哪些候选未确认、下一步怎么试。没有实际产物则省略产物区。

截图或名单输入需有对照表：原始名称 → 匹配项目 → 实际调用名 → 确认状态。保留未找到项和同名歧义，避免把替代项目当成原推荐。

## HTML 交互

多候选报告可提供按用途/输出类型筛选、关键词搜索、详情展开和提示词复制。完整截图可放大或打开原图，实际产物有入口。少量候选无需为了交互而增加控件。

- 面向分享者的成品不放讲者逐字稿、内部调试日志和无关聊天内容。
- 默认离线可打开；报告资源使用相对路径并一起打包，外部仓库链接标明需联网。
- 公开分享副本避免暴露本机用户名和绝对安装路径，详细安装位置可留在私有安装记录。
- 保留图片出处与“用户提供”标识，不把社媒作者的比较当作本次评测结论。
- 用语义按钮、可读对比表、清晰选中状态；长内容支持正常滚动，窄屏可阅读。

## 来源记录

能创建文件时在报告旁保存 `sources.json`，供以后复核和更新；仅聊天环境可在报告末尾列出同等来源与状态信息。按实际找到的信息填写，不为完整而编造字段：

```json
{
  "checked_at": "实际核查日期",
  "task": "本次任务",
  "execution_environment": "已确认的实际能力",
  "target_agent": null,
  "candidates": [{
    "input_name": "输入材料中的名称",
    "display_name": "核实后的项目名称",
    "call_name": null,
    "repository": null,
    "skill_path": null,
    "revision": null,
    "match_status": "unresolved",
    "source_urls": [],
    "claims": [],
    "installation": {"status": "not_attempted"},
    "trial": {"status": "not_run", "artifacts": []}
  }]
}
```

`claims` 可逐条记录能力判断及支持它的来源。安装成功需有安装器输出或文件核实，实测成功需有实际运行与产物检查。来源版本无法确定时写明，不伪造提交号。

## 交付检查

检查引用文件存在、链接指向正确对象、名单逐项有交代、报告不将未测试项写成已验证。使用环境可用的浏览器按用户偏好检查主要交互和窄屏；无法验证的部分如实说明。能创建文件时，最终报告与附属资源放在同一目录，需要转发时提供 ZIP。聊天环境不声称有本地文件或压缩包。
