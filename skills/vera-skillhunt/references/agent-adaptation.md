# 跨 Agent 适配

以能力选择做法，不按产品名假设能力。支持读取方法说明的 Agent 可以采用本流程，但联网、图片识别、生成文件和安装是否可执行取决于宿主。不要声称在所有 Agent 上已经验证兼容。

## 两个环境

- 执行环境：当前 Agent 实际能调用哪些工具？从系统提供的工具、宿主说明或已确认配置判断。
- 目标环境：用户希望候选 Skill 最终在哪里使用？未指定时沿用当前环境；远程或替别人查找时，不能把当前机器的安装状态当作目标状态。
- 只在差异会改变推荐或安装时追问，不要求用户填写技术问卷。

## 按能力选择执行方式

| 实际能力 | 做法 | 缺少时怎么继续 |
|---|---|---|
| 搜索或联网读取 | 搜索目录、GitHub，并阅读原始说明 | 分析用户给的文件和说明；需最新检索时请提供来源材料，标为未联网核实，不编造候选 |
| 图片读取 | 提取截图名称、作者和链接线索 | 请用户补可复制文字或链接，先处理能识别的部分 |
| 技能列表或配置读取 | 检查本地/目标环境已有能力 | 标“安装状态未检查”，不称为未安装 |
| 命令执行 | 可选用当前可用 CLI，先核实参数 | 用搜索/浏览工具替代检索；不把缺少终端当作无法做报告 |
| 文件或工件创建 | 生成 HTML、来源记录和资源包 | 交付 Markdown；指定 HTML 时给源码及保存方式，注明未生成文件 |
| 安装接口或目录写入 | 用户授权范围内，按目标宿主支持的方式安装 | 给与目标宿主匹配的安装步骤或打包文件；准确标为待用户安装 |
| 浏览器预览 | 检查交互、图片和布局 | 做能完成的结构检查，标明未做浏览器验证 |

## 安装与加载

优先使用目标 Agent 的原生安装/导入机制或其最新官方说明。明确支持 Skills CLI 时才使用 CLI 的目标标识和安装选项；不假设目录、`--agent` 值或自动发现规则通用。

文件复制、宿主发现、成功调用是不同阶段。分别记录已保存、已加载/待加载、已调用验证，不因复制成功就说已可用。是否需要新会话、刷新或重启，按宿主行为说明，不给统一要求。

本包的 `agents/openai.yaml` 仅是可选宿主元数据。核心是 `SKILL.md` 与 `references/`，其他 Agent 不需要读取该 YAML。不要将它改成其他平台配置或把包强行放入 Codex 路径。

## 三个验收情境

1. 有终端、联网和文件能力：可以搜索、生成报告；用户只要报告时不安装候选。
2. 能联网的聊天 Agent，没有文件写入和安装接口：给带来源的可读报告；不声称已保存 HTML 或已安装。
3. 离线、只有用户截图或文件：分析给定材料，标注来源未联网核实与不确定名称；不承诺最新排名。

这些是行为检查情境，不是已完成跨产品实测的证明。
