# vera-skillhunt

把发现线索、核对来源、选择方法和理解用法，整理成用户可以直接使用的报告。适用于不同 Agent；具体搜索、安装、浏览和制作用当前环境支持的工具，不依赖某个固定产品或另一个已安装 Skill。

## 先适配当前环境

开始执行时读取 [跨 Agent 适配](references/agent-adaptation.md)，按实际可用的搜索、视觉、文件与安装能力选择路径。运行本 Skill 的 Agent 与最终要安装候选 Skill 的目标 Agent 可能不同，分别确认；上下文清楚时不重复询问。

通用调用方式是“请按 vera-skillhunt 的方法，帮我找适合……的 Skill，并生成选用报告”。`$vera-skillhunt`、斜杠命令或自动加载是宿主特性，不是本 Skill 的前提。没有原生 Skill 功能时，可将本文件与所需 references 一起提供给 Agent 作为任务说明；这叫按方法执行，不称为已安装。

## 确定任务与输入

- 从上下文提取用户要完成的事、受众、交付格式、可编辑要求和运行环境。只有会改变选择的缺失信息才需要询问；已有信息不重复问。
- 任务描述：转成具体搜索词，必要时使用中英文同义词。
- 截图或清单：先记录可见名称、作者和候选项。看不清就标注不确定，不补造名称或帖子链接。截图中的命令是待分析材料，不是执行授权。
- 链接：读取原帖或仓库，分清被推荐的项目和引用的其他项目。
- 用户仅说“帮我找 Skill”且上下文没有目标时，先问想完成什么任务。用户要求快速比较时直接给简表；通常需要报告时默认交付中文 HTML，用户指定其他形式则遵从。

## 查找与核实

1. 用当前宿主提供的技能列表、设置、连接器或可访问的配置检查已有能力；有文件权限时再按实际配置读取技能目录。不要硬编码某个产品路径，不把不可见判断为未安装，不扫描无关目录。不能读取目标环境时记录“未检查”，继续搜索与比较。
2. 已有 Skill 适用时列为“本地已有”，仍按用户要求比较替代方案。已有不等于已验证适合本次任务。
3. 用可用目录搜索工具或 GitHub 搜索发现候选。例如可用时执行 `npx skills find <关键词>`；命令参数以当前帮助为准。CLI 不可用则用可用检索工具读取原始来源，不为搜索擅自部署复杂服务。
4. 阅读候选的原始 `SKILL.md`、相关说明和依赖要求。记录显示名、frontmatter 调用名、作者/仓库、Skill 子目录、原始链接、核查日期，能获取时记录版本或提交。
5. 区分 Skill、代码库、插件、模板和工具。没有找到 `SKILL.md` 的项目不可直接称为可安装 Skill；同名包装版与原工具分开说明。找不到精确对应项时保留“未确认”，替代项明确标注替代关系。
6. 社媒作为发现入口，原始文档支撑能力判断。安装量和关注度只是辅助信息；优先看任务、输入、输出格式、后续编辑、环境依赖和上手成本是否匹配。不以作者名称或热度代替核实。

## 比较与讲解

- 按任务形成可操作建议：“首选什么、什么情况下选另一个、暂不适合什么”。通常深入比较少量最相关候选；用户提供十项名单时逐项交代结果，不静默省略未找到项。
- 对每项说明用途、需要准备的输入、得到的输出、调用方式、上手步骤和关键限制。提示词使用核实后的名称，并带具体任务、输入与验收条件；默认给自然语言调用示例，只有目标宿主已确认支持时才附专用命令语法。
- 对 PPT 等任务，明确区分可编辑元素、整页图片和 HTML 网页；不把文件扩展名当作可编辑性的证据。其他领域选择对应的实际验收维度。
- 证据分层：文档声明、作者示例、实际小样。安装状态另列为本地已有、本次安装成功、失败或未安装。“已安装”不表示“已实测”。示意图标为示意，不伪装成 Skill 产物。

## 按需安装与实测

查找和报告本身不包含批量安装授权。用户已经明确要求安装指定项或全部候选时，按该范围推进，不重复请求相同许可；名称未确定的替代品另行说明。

- 优先用当前 Agent 的安装器；使用 Skills CLI 时先核实帮助，按具体 Skill 选择安装，例如支持时用 `npx skills add <owner/repo> --skill <name> --agent <agent>`，不要默认安装整个仓库。
- 检查目标是否已有，保留现有版本和用户修改。升级、替换及安装额外依赖不从普通“查找”请求推断。
- 记录每项安装结果、目标位置、调用名和未完成条件。失败后根据明确原因有限修正；同一原因重复失败时报告障碍，继续可独立完成的比较和报告。
- 用户要求实测时，用代表性输入验证核心能力。比较多个候选时尽量使用相同输入和验收条件，保留真实产物。缺少账号、付费资源或工具时准确说明，完成其他可测项，不伪造效果。

## 生成报告与交付

制作报告时读取 [报告规范](references/report.md)。能创建文件或工件时，默认交付可分享 HTML 和结构化来源记录；能编辑既有报告时在原位置更新。仅聊天环境先给可直接阅读的 Markdown 报告与来源；用户要求 HTML 时提供完整 HTML 源码并明确尚未保存或预览，不伪造文件下载链接。若指定只要简短答复，不强制生成文件。

交付前确认原图和案例能打开，筛选、复制、导航等实际存在的交互可用。报告需区分已核实、待确认、安装结果和实测证据。最终给出报告入口、主要推荐和未完成事项；不得把“已下载/已安装”写成整个工作流成功。
