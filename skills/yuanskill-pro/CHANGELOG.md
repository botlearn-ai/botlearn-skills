# CHANGELOG · yuanskill-pro

## v2.0.0 · yuanskill-pro（2026-08-16）

**一句话**：在 yuanskill v1「研究驱动的提示词优化器」之上，补齐它最大的两块空白——**skill 这一形态的工程细节**与**实测闭环**。

**基线**：yuanskill v1（旧版，未随分享包发布）

**新增来源**：《图解Skill：AI提效实战指南》（宝玉著，7 章通读）+ 对作者开源的 15 个 `baoyu-skills` 的**实物核对**。

## 三 · 新增了什么（自研，非书非 v1）

1. **实物核对优先于书面转述**（`01` §5）—— 本次评估的直接教训：书推荐"description 加反向触发词"，但作者自己 15 个开源技能一个都没用；书说"正文不超过 500 行"，他自己有技能 698 行。**不一致本身就是高价值发现**，据此下调该建议优先级。这条纪律书里没有。
2. **BASIC 模式也必须做一次基线对比**（`SKILL.md` 阶段 7）—— 书对自用技能的态度是"脑子里过一遍就够"，但 yuanskill 铁律 2 要求可验证。折中：BASIC 不建题库，但**至少跑一次有/无产物对比**，成本极低。
3. **对比维度表扩到 13 维**（`01` §6）—— 在原 10 维基础上加入 触发工程 / 上下文预算 / 实测闭环 三维。
4. **踩坑点区块（自举）**（`SKILL.md` 末节）—— 本 skill 自己带一份踩坑点，示范它教的做法。
5. **`assets/eval-kit.md`**（新增文件）—— 测试用例 / 检查项 / 记分表 / 变化清单四张可复制模板。理由：铁律 8「配套工程一起交」+ 铁律 12「交付即可用」——既然要求用户建题库，就得把模板给到。

## 四 · 明确没抄

| 没抄的 | 理由 |
|---|---|
| 书的方法论骨架本身（需求分析→设计→实现→测试→上线） | 它没有调研/对标环节。用它替换 yuanskill 的骨架＝退化 |
| 多技能编排（串联/并联/循环、子智能体、智能体团队） | 这是**用**技能的方法论，不是**造**技能的。全搬违反铁律 5「拒绝堆砌」。只在 `01` §2 保留"该不该拆成多个"的判定 |
| 评测循环的"手工版"松散度 | 作者自述自用"跑两遍就够"。抄机制要，抄松散度不要 |
| 反向触发词列为必需项 | 实物核对显示作者自己不用 → **降级为可选**（`02` §4.1 标注"装 20 个以上 skill 时才需要"） |

## 五 · 偏离原改造预案之处（须说明）

评估页（16 维对比取舍表，未随包发布）§⑤ 原定「**不新增第四个 reference 文件**」。实际执行时改变了这个决定：

- **原因**：全量集成后，原 `03-deliver-and-validate.md` 会从 50 行涨到 200+ 行，且职责变成"交付"与"验证"两件事。
- **依据**：书第 6 章「阶段三·架构重构」——补丁越打越多就该拆分；以及本版新采纳的「三层渐进式披露」——验证阶段的内容只在验证时才需要读，独立成文件更省上下文。
- **代价控制**：引用仍**只一层、不嵌套**（`SKILL.md` → `references/0X`、`assets/`，没有 A→B→C）。
- 文件重命名：`03-deliver-and-validate.md` → `03-deliver-and-engineering.md`（validate 部分移出），新增 `04-validate-and-iterate.md`。

## 七 · 交付前实测（阶段 7 · 本版自己走了一遍）

不只自审，真跑了一遍。方法：把本包复制成一个临时项目的项目级技能（**未改动 `~/.claude/skills`**），用无头会话实测。

**① 结构校验（自写检查器）—— 抓到 3 个真缺陷，均已修**

| 检查项 | 首轮 | 修复后 |
|---|---|---|
| 文件夹名与 `name` 一致 | ✅ | ✅ |
| description ≤200 字符（本版新立的规矩） | ❌ **230 字符，自己先违规** | ✅ 199 |
| 引用路径可解析 | ❌ 正文里有 `references/01` 这类短写法，解析不到 | ✅ 全部补成完整相对路径 |
| 引用只一层、不嵌套 | ⚠️ 误报 | ✅ 改判据为"目标能否从 SKILL.md 一跳直达"，二层文件间的横向互指不算嵌套 |
| 正文 ≤500 行 / ≤3800 汉字 | ✅ 98 行 / 2262 字 | ✅ |

> 这三个缺陷全部由**新版自己新增的规矩**照出来——评测循环第一次运行就抓到了自审漏掉的东西，正是 `04` §1 说的"自审只能查你已经想到的"。

**② 触发与跨文件加载测试**

| 用例 | 结果 |
|---|---|
| 点名调用 `yuanskill-pro`，问阶段 0.5 五种形态 / 铁律条数 / `assets/eval-kit.md` 内容 | ✅ 全部答对（五形态、12 条铁律、四张模板）——**说明 SKILL.md、references、assets 三处都能正常读到** |
| 真人说法「我有段 prompt 效果不太好，想认真打磨一下」 | ❌ **触发了旧版 `yuanskill`，不是 pro** |

**③ 基线冲突（重要，已写进安装说明）**

两版同时存在时，全局旧版 v1 抢到了触发。这不是 pro 的 description 写得不好，而是两者本就覆盖同一批触发词——**必须二选一**，或每次点名调用。这条是实测发现的，不是推测。
